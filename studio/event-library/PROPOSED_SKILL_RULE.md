# PROPOSED Slopcannon skill addition — the EVENT rule (parent applies; do NOT apply from the studio pack)

**Proposed insertion: Stage 3 (Plan), immediately after the scene table is
drafted and before the banger test. One new gate + one pointer line in
Stage 5 (QC).**

---

### Stage 3 addition — "EVERY SLOT CARRIES A NAMED EVENT (2026-11-13, user order)"

> The user, verbatim: *"bland events and same events makes a bland video."*
> A scene whose plan row is a subject at a place ("at the pier, she sings")
> is an atmosphere, not a scene. Before the banger test, every row of the
> scene table carries an EVENT column naming one happening from the studio
> Event Library (`~/workspace/wubumv/studio/event-library/EVENT_LIBRARY.md`)
> — start → peak → payoff, with the peak on a named beat or word.
>
> 1. **Distinct within the video.** No library event repeats across the
>    plan's rows. A returning motif is staged as a different event or an
>    explicit escalation, never a re-run.
> 2. **Checked against the ledger.** The plan is checked against
>    `USED_EVENTS.md` in the same directory: an event used in either of the
>    two most recent MVs needs a materially different staging (named in
>    the plan) or a different event. Signature-tier events (library
>    entries 1.1, 1.6, 3.1, 6.1, 10.5) never appear in consecutive MVs.
> 3. **Montage rows draw events, not atmospheres.** A montage row naming a
>    mood instead of a happening fails this gate.
> 4. **The intro slot takes a High-energy event**, already in motion at
>    frame 0 (extends the existing banger/cold-open rule from image to
>    happening).
> 5. **The vehicle leads with the event.** In every vehicle, the event
>    sentence (what happens, peak on its beat/word) is written before the
>    LOOK block and all other prompt detail.
>
> Full procedure: `studio/event-library/WORKFLOW.md` in the WUBUMV repo.
> A plan with no EVENT column, a duplicated event, or an unchecked ledger
> repeat FAILS Stage 3.

### Stage 5 addition — one line in the QC gate list

> **Event-read test:** for every shipped scene the QC record carries one
> sentence naming what HAPPENS in it. A scene whose honest sentence is
> "the singer sings at [place]" fails like a motion-law fail and the slot
> restages with a real event. The shipped master's event list is appended
> to `USED_EVENTS.md` as part of delivery bookkeeping.

---

*Rationale (for the parent, not part of the rule text): the founding
research (report at ~/workspace/research_notes/mv-event-library-2026-11-13/report.md)
found every canon video is remembered for a happening, and the seeded
ledger shows our last four builds spent the same two mechanics (glowing
carry-object + world-snap montage) — the exact repetition the user named.
This rule makes the event a planned, gated, ledgered unit like the word
grid, instead of a hope.*
