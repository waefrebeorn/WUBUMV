# Slopcannon intake — MV era checklist

A Suno track arrives from the user; it becomes the next MV project.
Run these steps in order. Nothing here is station-era: there are no
jobs, beds, or MUSIC_TAG registrations in the MV pipeline — a track
is a music video, full stop.

## 1. Receipt and project folder

- Accept the track as a chat attachment or as a file already placed
  in `musicvideo/intake/`.
- Create the project folder
  `~/workspace/wubutv-network/musicvideo/MV-<n>_<slug>/` with the next
  MV number. Music videos take their own numbers — never bumper,
  episode, or commercial numbers.
- Keep the delivered file as `track.mp4` — the Suno MP4 is the
  master, fingerprinted (md5), never overwritten or re-encoded.
  Extract `track.mp3` from it for analysis and transcription. (If an
  audio-only file is delivered instead, it is kept as `track.mp3`
  and that file is the master.)
- Save the user's lyrics verbatim in `lyrics.txt`. Owner text is
  canonical and never paraphrased — but the pasted sheet is not the
  timing authority where the performance differs (step 3).
- Log the receipt in `musicvideo/intake/INTAKE_LOG.md`: date,
  MV number + title, source, duration, track md5.
- Ask the rights question once (Stage 0): does the user own or hold
  licence for this track, and are the characters original? Log the
  answer in the project record.

## 2. Audio analysis FIRST — measured, never claimed

- Measure tempo and energy from the delivered audio before any
  planning. A prompt's stated BPM is a claim, not a measurement
  (MV-15: stated 152, measured 150.0; MV-9: stated 128, measured
  133).
- Measure duration with ffprobe; record it in the project notes.
- Write `AUDIO_ANALYSIS.md`: measured tempo, the measured beat
  grid, and the energy/section structure read off the audio.
- Re-time the scene grid to the delivered duration at once. A track
  longer or shorter than planned changes the scene count, never
  the song — the song is the tempo gospel. If the track is
  re-delivered, the timeline is re-measured and the old grid is
  void.

## 3. Performed word grid

- Extract the PERFORMED word grid from the audio: large-v3-turbo
  full-clip transcription as the backbone, never speech-VAD on
  chant singing; separated vocals only for dense spans where the
  mix loops. Where the performance differs from the pasted sheet,
  the performance is the authority.
- Write `LYRIC_TIMELINE.md` — measured section boundaries plus
  per-line start/end times, with confidence tags ([confirmed]
  measured, [inferred] section label or bracket estimate,
  [assumed] user claim) — and `SONG_WORDS.json` where the pipeline
  needs the machine-readable grid.

## 4. Reference stack and progress seed

- Build `REFERENCE_STACK.md` (+ `work/stills/stack/`) at plan
  time: the project's own autogenerated image-reference stack, one
  start/end pair per scene — never one anchor still reused across
  scenes (CONTINUITY METHOD, SKILL.md).
- Seed `MV<n>_PROGRESS.md` in the project root so the kickstand
  ladder has a state file from minute one.

## 5. Standing defaults (unless the user overrides per track)

- ONE 16:9 master only, AAC audio, house CRF 18. Chat delivery is
  a ≤50 MB size-capped encode of the same cut (Stage 7) — never a
  separate chat version, never a 9:16 reframe.
- Event-per-slot gate + USED_EVENTS check at plan time;
  montage-first; in-motion cuts only, no halted-photo starts;
  scene prompts lead with 'at <place>', not 'of <place>'.
- Any issue learned on one build goes through online research →
  improvement → SLERM before the next build inherits it (user
  order 2026-11-13). Delivered old MVs get no rework.
